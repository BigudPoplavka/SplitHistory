# Проекты и рабочие пространства

Проект — переносимая папка. Открытая папка является рабочим пространством: приложение читает Markdown рекурсивно и сохраняет изменения в эту же папку. Последняя папка открывается при следующем запуске. Один проект открыт в одном окне.

## Структура и формат

```text
Мой проект/
  .splithistory/
    project.json       # компактный JSON, formatVersion: 1
    trash/             # удалённые через приложение Markdown-файлы
  notes/<id>.md        # новые заметки приложения
  Obsidian/<import-id>/<исходная структура>/
  attachments/<note-id>/
  photos/<note-id>/
```

Индекс содержит слои, стабильные ID заметок, относительные пути, заголовки, теги, типизированные связи, даты, геометрию, цитирования, историю и прочие свойства модели. Текущее содержимое заметки хранится только в `.md`. Frontmatter и исходная разметка остаются внутри Markdown без преобразования; заголовок карточки хранится отдельно от имени файла. Переименование карточки не переименовывает файл и не ломает ссылки. Исторические версии текста по-прежнему сохраняются отдельно в истории заметки.

Выбран компактный UTF-8 JSON без отступов для индекса, обычный UTF-8 Markdown для текста и исходные бинарные файлы для вложений. Это компромисс размера, открытости и простоты редактирования:

- Нет второй полной копии текущего текста в индексе и экранирования его переносов строк внутри JSON.
- Убираются пробелы и отступы служебного JSON. Сжатие всего проекта при каждом автосохранении не требуется.
- Медиа не кодируются в Base64, которое увеличивает полезный объём примерно на треть. Копируются исходные файлы.
- Неизменённые Markdown не переписываются. Для обнаружения внешних правок индекс содержит SHA-256 текста каждой заметки; это небольшой фиксированный расход на заметку.
- Дополнительной базы данных и зависимостей для хранения не требуется. SQLite разумно рассмотреть, когда появится необходимость в дисковых индексах и выборках для больших хранилищ. Сейчас приложение загружает граф целиком.

Это не утверждение о минимальном размере любого возможного архива: ZIP обычно меньше для текстов и подходит для передачи папки, но неудобен для прямой работы с `.md`. На диске множество небольших файлов также расходует место на кластеры файловой системы. Гарантировать выигрыш относительно каждого монолитного формата нельзя; выбранный формат избегает ненужного дублирования и сохраняет требуемую совместимость с Markdown.

## Команды

- **Файл → Новый проект** (`Ctrl+N`): выберите или создайте пустую папку.
- **Открыть папку как рабочее пространство** (`Ctrl+Shift+O`): откройте существующий проект либо любую папку с Markdown. При первом открытии создаётся служебный индекс, заметки попадают на слой «Обсидиан».
- **Импорт Obsidian (хранилище или подпапка)**: сначала откройте целевой проект, затем выберите исходную папку.
- **Сохранить** (`Ctrl+S`), автосохранение и сохранение перед закрытием пишут изменения в открытую папку.
- **Сохранить копию проекта / хранилища** (`Ctrl+Shift+S`): для проекта выберите другую пустую папку; копируются заметки, индекс и вложения, после чего открывается копия.
- **Открыть хранилище** (`Ctrl+O`): совместимость с прежними монолитными `vault.json`. Для них сохраняется прежний режим хранения; для новых проектов используйте команды папок.
- Экспорт GraphML/GeoJSON/CSV, импорт BibTeX, показ папки и выход остаются в меню.

## Импорт Obsidian

Импорт создаёт независимую копию в `Obsidian/<import-id>/`, сохраняя структуру относительно корня исходного vault. Каждый импорт получает отдельное пространство путей, чтобы одинаковые имена из разных хранилищ не смешивались. Все импортированные заметки размещаются на одном слое «Обсидиан». Повторный импорт создаёт новую копию, а не синхронизирует предыдущую.

Для подпапки ищется ближайший родитель с `.obsidian`. Из выбранной папки копируются файлы, затем рекурсивно добавляются заметки и вложения, доступные по её исходящим ссылкам внутри vault. Поэтому импорт подпапки может включать связанные файлы за её пределами. Несвязанные заметки и заметки, имеющие только входящую ссылку в выбранную папку, не включаются. Если `.obsidian` отсутствует, выбранная папка считается корнем: внешние зависимости автоматически обнаружить нельзя.

Обрабатываются `[[Заметка]]`, `[[папка/Заметка.md#Заголовок|подпись]]`, ссылки на блоки, `[подпись](относительный%20путь.md)` и `![[медиа]]` / `![подпись](путь)`. Относительные пути, пути от корня и уникальные короткие имена разрешаются в исходном пространстве файлов. Неоднозначные и отсутствующие назначения остаются в исходном тексте и выводятся в отчёте после импорта. Ссылки внутри блоков кода не становятся рёбрами графа. Протоколы внешних URL не используются для чтения файлов.

Текст, frontmatter, Markdown, якоря, алиасы в ссылках и медиа сохраняются. Теги из `tags` / `tag` (простая YAML-строка, список в скобках или блочный список) и обычные `#теги/вложенные` добавляются в модель. Сложные YAML-конструкции сохраняются в тексте без полной интерпретации.

В просмотре доступны переходы к заметкам, локальные изображения, аудио/видео поддерживаемых Chromium форматов и открытие других вложений, включая PDF. Ссылка на заголовок/блок открывает заметку целиком. Встраивание другой заметки отображается как переход. Callouts, Dataview, Canvas и плагины Obsidian не исполняются; исходный Markdown сохраняется даже там, где упрощённый просмотр приложения не воспроизводит оформление.

Форматы ссылок и вложений сверены с официальной документацией: [Internal links](https://obsidian.md/help/links), [Attachments](https://obsidian.md/help/attachments), [Properties](https://help.obsidian.md/properties).

## Сохранность и ограничения

При импорте исходные файлы не изменяются. При открытии папки как рабочего пространства последующие правки сохраняются непосредственно в ней. Не импортируются скрытые каталоги (включая настройки и плагины), `node_modules` и символические ссылки. Относительные пути проекта проверяются на выход из папки.

Запись каждого Markdown и индекса выполняется через временный файл и переименование. Это атомарность отдельного файла, а не транзакция всей папки: резервные копии проекта по-прежнему полезны. Удалённые через приложение ранее сохранённые заметки перемещаются в `.splithistory/trash`; вложения автоматически не удаляются. При открытии и сохранении пользовательские файлы не должны изменяться одновременно другим приложением: внешний конфликт блокирует запись вместо перезаписи текста. Для чтения внешних изменений используйте **Вид → Обновить**; это перезагружает данные с диска и отбрасывает несохранённые правки окна. Автоматического наблюдения за папкой и слияния изменений пока нет.

Индекс сохраняет дополнительные свойства; без него можно восстановить Markdown и текстовые связи, но нельзя восстановить вручную назначенные слои, даты и геометрию. Переносите всю папку проекта. Пока импорт и сохранение выполняются синхронно в главном процессе: очень большие vault могут задерживать интерфейс.

## Проверка

`npm test` проверяет разрешение путей, неоднозначные имена, теги, импорт подпапки с транзитивными зависимостями и медиа, сохранение BOM/CRLF, перенос папки, стабильные ID и связи, защиту внешних изменений, корзину и запрет выхода за пределы проекта. Проверку меню и отображения медиа в Electron нужно дополнительно выполнить вручную: создать проект, импортировать vault, открыть заметку, изменить её, закрыть и заново запустить приложение, затем открыть сохранённую копию.
